# 雙軌回饋成長迴圈

「答不出來」跟「答錯了」是兩種本質不同的失敗，值得分開追蹤：

- **知識缺口**——agent 誠實地說「查無資料」，代表知識庫有缺口需要補。
- **倒讚回饋**——agent 給了答案，但使用者說這是錯的，代表現有知識或邏輯有問題需要修正。

兩者混在一起會讓後續的資料很難用——知識缺口暴增代表的是內容覆蓋率不足，答錯回報暴增代表的是既有內容或檢索邏輯出問題，兩種根因對應的修復動作完全不同。兩條軌道各自建立獨立的清單，透過 Power Automate 排程，固定週期（例如每週一早上）自動寄送彙整報告給維護者，不用每天手動盯著看。

## 回報體驗的細節設計：不用重打一次問題

每個答案下方固定附一個「答案有誤？」的快速回報入口。回報當下，系統會沿用對話過程中已經存在的上下文——剛才使用者問了什麼、agent 剛剛怎麼回答，這些都已經存在全域變數裡——直接帶入回報表單，使用者只需要補「哪裡錯了」跟「期望的答案是什麼」這兩項，不需要重新打一次原本的問題。

這個細節的分量比它聽起來重要：使用者要多打一次字，就是一次「乾脆算了」的機會。把回報門檻降到最低，才會有人真的願意去點那個按鈕——這也是為什麼知識缺口與倒讚回饋的資料量，能撐得起「上線後持續追蹤正確率」這件事（詳見 [README](../README.md) 的方法論與評估）。

## 為什麼這個迴圈成立

兩條軌道單獨看都不夠：一堆「查無資料」紀錄沒有排序優先度，只會變成一堆噪音；一筆「答錯了」的回報沒有持續追蹤，修一次之後换個問法又會重新發生。兩者都用固定週期持續追蹤，才能把「agent 上線那天的品質」變成「agent 會隨時間持續變好」——而不是上線當下的品質就是它永遠的品質。
